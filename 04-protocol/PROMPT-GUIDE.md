# PROMPT-GUIDE.md — איך כותבים פרומפט טוב ל-Lovable

> כללים שנלמדו מניסיון בפרויקט הזה. עדכן כשלומדים משהו חדש.

---

## מבנה פרומפט — 3 חלקים

```
[הקשר]   מה קיים / על מה בונים
[דרישה]  מה בדיוק רוצים — ספציפי, עם מספרים ושמות
[מגבלות] מה אסור לגעת בו
```

---

## 7 כללי הזהב

### 1. פרומפט אחד = מסך אחד (או תיקון אחד)
לעולם לא "תבנה את כל האונבורדינג". Lovable עושה עבודה טובה על משימה ממוקדת ועבודה גרועה על משימה רחבה.

### 2. תמיד לסיים ב"אל תיגע ב..."
Lovable אוהב "לשפר" דברים שלא ביקשת. כל פרומפט מסתיים ב:
```
Do NOT modify the existing Dashboard or any other existing screens.
```

### 3. טקסטים בעברית — נותנים מוכנים
אם לא נותנים את הטקסט המדויק, Lovable ימציא עברית קלוקלת.
כל label, כותרת וכפתור — כתובים מראש בפרומפט.

### 4. RTL — להזכיר בכל פרומפט
```
Hebrew RTL layout. Sidebar on the RIGHT.
```
גם אם זה ב-Project Knowledge — לחזור על זה. Lovable שוכח.

### 5. Routes — לתת שמות מפורשים
```
Route: /onboarding/upload
```
אחרת Lovable ימציא מבנה נתיבים משלו.

### 6. לבדוק מה Lovable הוסיף מעצמו
אחרי כל build — לקרוא את הסיכום שלו. הוא מוסיף דברים שלא ביקשת
(למשל: כפתור "דלג", משפטים שיווקיים). לתקן מיד, לא לצבור.

### 7. עיצוב — reference למה שקיים
```
Match the existing design system of the dashboard.
```
לא לתאר עיצוב מאפס — להפנות למה שכבר בנוי.

## תבנית מוכנה — העתק ומלא

```
Build [שם מסך] ([מזהה מ-SCREENS.md]).

Requirements:
- Route: /[path]
- [רכיב 1 — עם הטקסט העברי המדויק]
- [רכיב 2]
- [התנהגות: מה קורה בלחיצה]
- Design: Hebrew RTL. Match the existing design system.

Do NOT modify [רשימת מסכים קיימים].
```

## טעויות שכבר עשינו (ולא נחזור עליהן)

| טעות | לקח |
|------|-----|
| בנינו Welcome בעברית כשהדשבורד באנגלית | להחליט שפה גלובלית לפני מסך ראשון |
| Lovable הוסיף "בלי הזיות" לטקסט שיווקי | לתת את כל הטקסטים מראש |
| Lovable הוסיף כפתור "דלג" לא מבוקש | לקרוא את הסיכום של כל build |

- [ ] כל הטקסטים העבריים כתובים במלואם?
- [ ] יש שורת "Do NOT modify"?
