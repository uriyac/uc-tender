### 2.2 ענפים, PRs ומיזוג (D-04)
- **סוכן קוד אחד** דוחף, ורק לענפים. לעולם לא ל-`main`.
- **רק אוריה ממזג.**
- ענף: `<task-id>-<slug>`, למשל `BE-04-no-default-passwords`.
- קומיט: `<TASK-ID>: <תיאור>`. כותרת PR: `[<TASK-ID>] <תיאור בעברית>`. גוף ה-PR: קריטריון הסיום, איך אומת, `Refs #n` אם יש issue, ושורת סטטוס.
- משימה אחת בכל PR. PR שנוגע ביותר מ-8 קבצים (בלי קבצי lock) או משנה את חוזה המנוע דורש תוכנית מאושרת לפני שמתחילים.
- עבודה מתחילה רק כשהמשימה "מאושר" ב-`tasks.md` והתלויות סגורות.

### 2.3 patches לבוטים שלא דוחפים

### 2.7 דיווח סטטוס
קובץ `/workspace/plan/status/<TASK-ID>.md`, שורה חדשה בכל עדכון:
```
<תאריך שעה, שעון ישראל> | <TASK-ID> | <בוט> | STATUS: DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT
מה נעשה: …   ראיה: <PR/קומיט/נתיב>   חסם או חשש: …   מה צריך ממי: …   עד מתי: …
```
- DONE: הקריטריון התקיים. DONE_WITH_CONCERNS: התקיים, עם חשש מפורט. BLOCKED: חסום (מציינים ID או D-xx). NEEDS_CONTEXT: חסר מידע (מציינים ממי).
- "אסטרטגיה ומוצר" מעדכן את `tasks.md` פעם ביום לפי קבצי הסטטוס.
