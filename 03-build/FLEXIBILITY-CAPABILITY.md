# יכולת גמישות מקצועית — התאמת נכס למכרז (Asset↔Tender Tailoring)

> "עוד קומה" מעל לולאת הלמידה. הבידול המרכזי של UC TENDER, מזוקק לכדי יכולת מפורשת.
> **האנלוגיה המנחה:** התאמת פרויקט למכרז = **התאמת קורות-חיים למשרה**. מועמד טוב לא משקר —
> הוא מדגיש את הרלוונטי, מאמץ את שפת המשרה, וממסגר ניסיון סמוך כך שיענה על הדרישה.

---

## 1. מה זו היכולת

בהינתן **נכס** (פרויקט/ניסיון/יכולת מהזיכרון הארגוני) ו**דרישת מכרז ספציפית**, המערכת מפיקה
**הצגה תפורה** של הנכס למכרז הזה:
- **מה להבליט** — אילו ממדים של הנכס עונים על הדרישה.
- **איך לנסח** — בשפת המכרז (אימוץ המונחים שלו), לא בשפה גנרית.
- **הגשר** — כשההתאמה סמוכה (לא ישירה): משפט שמסביר מדוע הניסיון רלוונטי.
- **חלופות** — יותר מניסוח אחד, לבחירת המשתמש.

**הגבול (קדוש):** מסגור-מחדש והדגשה — **לא** המצאה. כל טענה קשיחה (כמות/תקן/שנה) חייבת מקור
בנכס עצמו. ה-guardrail הקיים אוכף זאת דטרמיניסטית. גמישות = *איך מציגים את מה שיש*, לא *להמציא מה שאין*.

---

## 2. שלוש השכבות

| שכבה | מה עושה | סטטוס |
|------|----------|-------|
| **בחירה** (Selection) | לכל דרישה — איזה נכס הכי מתאים (ישיר/סמוך) | ✅ קיים ב-`buildMapping` (`relevance`, `bridge`) |
| **תפירה** (Tailoring) | הצגה מותאמת: הבלטת ממדים + ניסוח בשפת המכרז + חלופות | 🆕 **הקומה החדשה** |
| **למידה** (Learning) | תפירה/מסגור שזכו בעבר → מועדפים; מפרסם X אוהב ניסוח Y | 🔗 מתחבר ל-S4 |

---

## 3. למה זה עדיף מכל מערכת רגילה

- כלי RFP רגיל **שולף** פסקה קיימת מספריית-תוכן (retrieval). אנחנו **תופרים** את הנכס לדרישה
  הספציפית — כמו קו״ח שנכתב מחדש לכל משרה, לא קו״ח אחיד שנשלח לכולם.
- זה **מרחיב את מרחב המכרזים** שהלקוח יכול לגשת אליהם: לא רק מכרזים בהתמחות המדויקת, אלא גם
  **סמוכים** — שם התפירה יוצרת את היתרון. (זה בדיוק הכאב מהראיונות: חברות מפספסות מכרזים
  שהן *כן* מתאימות להם, כי לא ידעו למסגר.)
- עם ה-guardrail — התפירה **בטוחה**: לעולם לא חוצה לבדיה, כך שהיתרון בא בלי סיכון פסילה.

---

## 4. פלט היכולת (מבנה מוצע)

לכל התאמה (דרישה × נכס):
```
tailoring = {
  requirement, asset (project),
  relevance: 'direct' | 'adjacent',
  stretch: 'direct' | 'adjacent' | 'stretch',   // שדרוג #1: מד-מתיחה — כמה הרחקנו במסגור
  evidence_tier: 'strong' | 'bridged' | 'weak', // דרגת-ראיה — עוצמת הביסוס
  emphasize: [dimensions...],        // מה להבליט — תת-קבוצה של ממדי הנכס בלבד
  tender_language: [terms...],       // מונחי המכרז לאימוץ (רק אם ממד תומך — אנטי-stuffing)
  bridge: string,                    // גשר (לסמוך), מעוגן בממדים
  variants: [ניסוח א', ניסוח ב'],    // חלופות לבחירה (הבחירה = אות-העדפה ללמידה)
  fit_score: 0-100,                  // עוצמת ההתאמה (מכויל בעתיד מהלמידה)
  sources: [asset dimensions used]   // אפס-הזיות: כל מה שנטען מגיע מכאן
}
```
**כלל תצוגה:** תפירה ללא ≥1 ממד תומך קונקרטי (evidence_tier='weak' בלי ביסוס) — **לא מוצגת** (מונע פלאף).
`stretch='stretch'` מוצג למשתמש כאזהרה גלויה ("זו מתיחה") — עדיף כנות על מכירת-יתר.

---

## 5. איך זה נבנה (Claude-ready, guardrail)

- **key-free עכשיו:** תפירה היוריסטית — הבלטת הממדים החופפים (מ-`overlap`), אימוץ מונחי המכרז
  שכבר מזוהים ב-`parseTender`, וניסוח-תבנית. חלופות = תבניות שונות.
- **Claude בהמשך:** תפירה עשירה — ניסוח טבעי בשפת המכרז, גשרים חכמים — מאחורי אותו חוזה,
  עם אותו guardrail (כל טענה קשיחה מעוגנת בממדים; אחרת נחסמת).
- **חיבור ללמידה (S4):** תפירה שהופיעה בהגשה שזכתה → `fit_score` מוגבר; ניסוח שמפרסם קיבל → מועדף.

### ארבעת השדרוגים מההתייעצות (נעולים בגישה)
1. **מד-מתיחה + דרגות-ראיה** — `stretch` + `evidence_tier`. המערכת אומרת "זו מתיחה" במקום למכור יתר → יותר אמין, מגן מפסילה טכנית.
2. **ללמוד את המסגור שזוכה** — לא רק תוכן; ה-variant שזכתה → מועדפת (מתחבר ל-S4.4 ראיות מנצחות, שכבר מתייגות `source:'הגשה זוכה'`).
3. **חלופות כלמידת-העדפה** — בחירת המשתמש בין ניסוחים = אות-למידה (preference), הופך לקו-פיילוט.
4. **אנטי-keyword-stuffing** — מונח מ-`tender_language` נכנס **רק** אם ממד אמיתי תומך בו (אימוץ סמנטי, לא הזרקה עיוורת שבודקים מענישים).

## 5b. רשת-אימות (F0) — test-first, לפני קוד תפירה

הלב לא נבנה "לפי תחושה". קודם רשת, ואז כל שורת תפירה נמדדת מולה:
- **הרחבת ה-guardrail לתפירה** — `enforceDraft` יכסה גם `emphasize`/`bridge`/`variants`: כל עובדה קשיחה מעוגנת בממדים, אחרת נחסמת. + טסטים.
- **סוויטת "צריך-להישאר-פער"** — תרחישים אדוורסריים (כמו "כור גרעיני") שבהם התשובה הנכונה היא `gap`; מוודאים שהמערכת לא תופרת יש-מאין. **ה-failure-mode הקריטי.**
- **golden-set** ב-`measure.mjs` — fixtures `(נכסים, דרישה, expected:{should_match, expected_relevance, must_emphasize, must_not_claim})`. מדדים: נאמנות (0 מזויף) · כיסוי (ממדים נכונים) · כנות (out-of-domain=gap).
- **מדד-על (איטי, דרך S4):** win-rate על מכרזים **סמוכים** — ההוכחה הסופית.
