## החלטות-יסוד (מנחות את כל התוכנית)

| החלטה | הבחירה | השלכה על הבנייה |
|-------|--------|------------------|
| מנוע Claude | **בעתיד.** עכשיו — שלד key-free ברמה גבוהה, מוכן ל-drop-in | כל פונקציית מנוע חייבת parity stub↔claude + מטא-דאטה (confidence+source) בכל פלט |
| פרסונה | **רב-תחומי (כללי)** | טקסונומיית דרישות גנרית; בלי הנחות סקטור |

| יעד | **פיילוט חי** | כולל פריסה, אימות, אונבורדינג, מדידה |

**עקרון-על לאורך כל התוכנית — "Claude-ready":** כל שיפור נבנה מאחורי חוזה המנוע (`engine()`), כך שהמעבר ל-Claude הוא החלפת implementation אחד, לא שכתוב. אף רכיב חזית/route לא קורא ישירות ל-stub.

## S3 — חבילת הגשה + מילוי טפסים רשמיים ⭐ (הפער הקריטי) ✅ הושלם 2026-08-30
**מטרה:** לעבור מ"טיוטה" ל**פלט שאפשר להגיש** — טפסים רשמיים ממולאים + חבילה שלמה. עם אפס-הזיות.
**אומת:** 15/15 טסטים · צינור מלא (packet-smoke) · e2e בשרת (PDF 607KB) · חזית מחווטת · עברית אושרה ויזואלית.
**ממצא:** pdf-lib מציג עברית נכון בסדר לוגי (בלי היפוך RTL — שלא כמו pdfkit).

**גישה טכנית (Node, בלי מפתח):**
- **AcroForm** (טפסים עם שדות) → `pdf-lib` ממלא שדות לפי שם, ומשטח (flatten).
- **טופס שטוח** (בלי שדות) → overlay טקסט לפי קואורדינטות ממפת-שדות לתבנית.
- **רישום תבניות** — לכל טופס רשמי מוכר: field-map (שמות שדות AcroForm או קואורדינטות).
- **אפס-הזיות** — ממלאים רק שדה שיש לו ערך עם מקור בפרופיל/ידע; שדה לא-ידוע נשאר ריק ומסומן בצ׳קליסט.

| # | תת-שלב | פירוט |
|---|--------|-------|
| S3.1 | **חילוץ שדות טופס** | זיהוי AcroForm; אם אין — מסלול תבנית-קואורדינטות |
| S3.2 | **מיפוי שדה→פרופיל** | חיבור כל שדה לנתון בפרופיל/ידע החברה; מה שאין — מסומן GAP |
| S3.3 | **מילוי + השטחה** | `pdf-lib` → טופס ממולא; ערכים עם מקור בלבד |
| S3.4 | **צ׳קליסט מסמכים נדרשים** | נגזר מהמכרז (S1.2); ✓ מה שיש במאגר, ✗ מה שחסר |
| S3.5 | **צ׳קליסט חתימות/חותמות/אימותים** | היכן נדרשת חתימה מורשה/חותמת/נוטריון |
| S3.6 | **ייצוא חבילה** | ZIP: טפסים ממולאים + מסמך מענה + צ׳קליסטים + עמוד-שער |

**DoD:** מכרף-דמו עם טופס רשמי → חבילת ZIP מורדת; שדות ממולאים רק ממקור; כל שדה/מסמך חסר מסומן ברור.

**הערה על היקף:** נתחיל מ-1–2 תבניות טופס רשמיות נפוצות; רישום-התבניות מאפשר הרחבה בלי קוד חדש.

## מדדי הצלחה (לאורך כל השלבים)
- **Time-to-submission-packet** — כמה מהר ממכרף לחבילה מוכנה.
- **% דרישות עם מקור** — יעד 100% (אפס-הזיות).
- **0 פסילות טכניות** — צ׳קליסטים תפסו כל דרישה/חתימה.
- **Edit-distance** על הפלט — כמה הלקוח תיקן ידנית (יורד עם הלמידה).
- **שיפור ביטחון לאורך זמן** — מדד ה-moat.
