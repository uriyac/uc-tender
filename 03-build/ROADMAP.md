## עקרון החלוקה

השאלה לכל פיצ'ר היא לא "האם זה טוב?" אלא "האם צריך את זה כדי להוכיח שהרעיון עובד?"

- **MVP** = הדבר הקטן ביותר שמוכיח את הגמישות המכרזית מול משתמש אחד.
- **Phase 2** = מה שהופך מוכחות-רעיון למוצר שאנשים משלמים עליו.
- **Phase 3** = מה שהופך מוצר למתחרה של Responsive/AutoRFP.

## 🎯 MVP — מוכיח את הרעיון

הליבה שכבר הגדרנו ב-MVP.md, פלוס שדרוג אחד מהמחקר.

| # | פיצ'ר | מקור במחקר | סטטוס |
|---|--------|-------------|--------|
| 1 | העלאת מסמכים + זיכרון ארגוני | הליבה שלנו | ✅ נבנה (B02) |
| 2 | סקירת ידע + עריכה | הליבה שלנו | 🔄 הבא (B03) |
| 3 | קליטת מכרז + פענוח דרישות | Document Shredding (כולם) | ⏳ Sprint 2 |
| 4 | Match Score + Gap Analysis | Fit Analysis (Responsive) | ⏳ Sprint 2 |
| 5 | חולל טיוטה + גמישות מכרזית | RAG generation (AutoRFP) | ⏳ Sprint 3 |
| 6 | תגית מקור + ציון ביטחון לכל פסקה | TRACE (Responsive) / Trust Layer (AutoRFP) | ⏳ Sprint 3 — חדש מהמחקר |
| 7 | Guardrail: נתון חסר = מסומן, לא מומצא | Grounding / Hallucination Prevention | ⏳ Sprint 3 |

**השדרוג היחיד שנכנס מהמחקר:** ציון ביטחון + ציטוט מקור. זול לבנות (בעיקר UI מעל לוגיקה בסיסית), ומייצר בדיוק את האמון שמונע פסילות. כל השאר מהמחקר — למטה.

## 🚀 Phase 2 — הופך למוצר שמשלמים עליו

נבנה רק אחרי ש-3-5 משתמשי פיילוט הוכיחו שהליבה עובדת.

| פיצ'ר | מקור | למה לא ב-MVP |
|--------|------|--------------|
| נעילת "מילה-במילה" לסעיפים משפטיים | Word-for-Word (Loopio) | דורש ליבת generation יציבה קודם |
| Go/No-Go מתקדם עם קריטריוני Deal-breaker | Go/No-Go Agent (AutoRFP) | ה-MVP עושה Gap בסיסי — זה השדרוג |
| ניתוב משימות למומחים (SME routing) | RACI Routing (כולם) | דורש כמה משתמשים בארגון — לא רלוונטי למשתמש בודד |
| למידה אוטומטית מכל הגשה שאושרה | Self-Updating Library (AutoRFP) | דורש בסיס נתונים בשל + היסטוריית שימוש |
| דשבורד אנליטיקה (Win/Loss, זמן ממוצע) | Analytics (Responsive/Loopio) | צריך נתונים אמיתיים כדי שיהיה שימושי |
| מחוון רעננות תוכן (Content Freshness) | AutoRFP / Loopio | תוספת ל-Phase 2 של הזיכרון |

## 🏢 Phase 3 — מתחרה בגדולים

דורש צוות, מימון, ותשתית אבטחה רצינית. לא לפני שיש הכנסות.

| פיצ'ר | מקור | הדרישה האמיתית |
|--------|------|------------------|
| אינטגרציות חיות (Drive, SharePoint, Salesforce, Notion) | Self-Updating Library | צוות הנדסה + תחזוקת API |
| תוסף דפדפן למילוי פורטלים | Portal AutoFill (AutoRFP) | פיתוח extension + תחזוקה מתמדת |
| ניתוב ל-Slack / Teams כאפליקציה מוטמעת | Workflow (כולם) | אינטגרציות ארגוניות עמוקות |
| ניתוח מתחרים + Price-to-Win | AutogenAI / Thalamus | מודל AI מתקדם + נתוני שוק |
| תקני אבטחה: SOC 2 Type II, ISO 27001, FedRAMP | NFR (כולם) | חודשי audit + עלות גבוהה |
| חיפוש סמנטי מלא מבוסס RAG + embeddings | AI-Native core | תשתית ML רצינית |
| מודל תמחור "משתמשים ללא הגבלה" | AutoRFP pricing | החלטה עסקית, לא טכנית |

## 🧭 החלטה אסטרטגית פתוחה

המחקר החדש עוסק ב-RFP מסחריים גלובליים (שאלוני אבטחה, DDQ, כל מכרז).
ה-PRD המקורי עוסק במכרזים ציבוריים בישראל.

זו החלטה שצריך לקבל לפני Phase 2 — אבל לא חוסמת את ה-MVP, כי הליבה (זיכרון ארגוני → גמישות → טיוטה) זהה בשני המקרים.

**להכריע עד:** תחילת Sprint 2.

---

## מה המחקר לימד אותנו — התובנות שמנחות הכל

1. **AI-Native מנצח את הוותיקים** בזכות אפס-תחזוקה-ידנית. זה בדיוק הזיכרון הארגוני החי שלנו — זה ה-moat.
2. **מניעת הזיות היא חסם האימוץ מספר 1.** כל שחקן פתר אותה עם עיגון למקור + ציון ביטחון. חובה אצלנו.
3. **תמחור מבוסס-מושב פוגע ב-SME.** הוותיקים מפסידים כי מומחים לא נכנסים למערכת. הזדמנות עתידית.
4. **הערך האמיתי הוא לא "חיסכון בזמן" אלא "מכפיל כוח"** — לאפשר לצוות קטן להגיש ברמת תאגיד. זה ה-positioning.
